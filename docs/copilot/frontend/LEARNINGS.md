# Athlify Frontend – Copilot Learnings

This file records durable, evidence-backed frontend knowledge. Planned
behavior belongs in the concept and PRD; implemented behavior is confirmed
against source code and tests.

Each entry uses the shared format:

`YYYY-MM-DD - \`scope\` \`status\` Rule. Why: why it matters. Evidence: source.`

See the [shared learnings template](../../../.agents/skills/project-docs/references/learnings-template.md).

## Learnings

- 2026-09-23 - `frontend` `superseded` ~~The checkout contains a React/Vite JavaScript scaffold without product behavior.~~ Superseded: the app is now TypeScript (`.tsx`) with Chakra UI, routing, i18n and prototype charts, still without product behavior or backend integration. Why: New UI work must distinguish exploration code from implemented domain functionality. Evidence: [`package.json`](../../../src/frontend/athlify/package.json), [`MyApp.tsx`](../../../src/frontend/athlify/src/MyApp.tsx).
- 2026-09-15 - `frontend` `durable-rule` The frontend owns presentation and interaction but consumes backend-owned data shapes, calculations, authorization and synchronization behavior. Why: Duplicating domain rules in components creates divergent values and unsafe assumptions about personal data. Evidence: [`SAD.md`](SAD.md), [`../backend/SAD.md`](../backend/SAD.md).
- 2026-09-15 - `frontend` `durable-rule` Every data-dependent view distinguishes loading, empty, error and populated states, and every action provides clear feedback. Why: Empty or failed requests must not look like successful zero-valued data. Evidence: [`SAD.md`](SAD.md), [`PRD.md`](PRD.md).
- 2026-09-15 - `frontend` `durable-rule` The UI supports German and English while documentation, source code, routes, identifiers and technical terms remain in English. Why: Translation resources can handle visible text without making domain contracts or code identifiers ambiguous. Evidence: [`README.md`](README.md), [`../../GLOSSARY.md`](../../GLOSSARY.md).
- 2026-09-23 - `frontend` `superseded` ~~The initial scaffold must not introduce API, routing, persistence or domain behavior.~~ Superseded: routing (`react-router-dom`) and i18n were added on purpose. API calls, persistence and domain rules are still not implemented in the frontend. Why: Keeps the frontend/backend seam reversible until the GraphQL contract is agreed. Evidence: [`MyApp.tsx`](../../../src/frontend/athlify/src/MyApp.tsx), [`../adr/ADR-001-graphql-api-contract.md`](../adr/ADR-001-graphql-api-contract.md).
- 2026-09-15 - `cross-cutting` `durable-rule` Functional product documentation remains under `docs/concept/`, while the configured AI documentation root is `docs/copilot/`. Why: Contributors need a separate functional source of truth and one configured location for implementation context. Evidence: [`.agents/docs-root`](../../../.agents/docs-root), [`../../README.md`](../../README.md), [`../README.md`](../README.md).
- 2026-09-16 - `frontend` `verified` TypeScript is now production-ready: compiler installed, `tsc -b` gates the build (using project-reference composite mode), and ESLint covers `.ts/.tsx` files. Why: Type errors now fail the build before Vite; strict mode catches issues at edit time and build time. Evidence: `src/frontend/athlify/package.json` build script, `tsconfig*.json` composite mode, `eslint.config.js` TypeScript coverage.
- 2026-09-16 - `frontend` `verified` TailwindCSS v4 is the chosen styling framework; uses `@tailwindcss/vite` plugin and CSS-first `@import "tailwindcss"` directive. No `postcss.config.js` or `tailwind.config.js` needed for defaults. Why: Vite plugin approach is lighter, automatic content scanning, and tree-shaking works by default. Evidence: `src/frontend/athlify/vite.config.ts`, `src/frontend/athlify/src/index.css`.
- 2026-09-23 - `frontend` `open` State management, the GraphQL client, the Tailwind/Chakra coexistence, the final chart approach, and the representations for missing-data TSS, Indoor/Outdoor, tags and merge membership are still undecided. Why: These choices affect API adapters, inputs, filters and component boundaries. Evidence: [`SAD.md`](SAD.md), [`adr/ADR-002-chakra-ui-component-system.md`](adr/ADR-002-chakra-ui-component-system.md), [`../../concept/activity-management.md`](../../concept/activity-management.md).
- 2026-09-23 - `frontend` `pitfall` Chakra UI CLI snippets in `src/components/ui/` violate `react-refresh/only-export-components` and `@typescript-eslint/no-empty-object-type`. `eslint.config.js` therefore disables both rules for `src/components/ui/**`. Put generated snippets there and keep hand-written components outside that folder. Why: Snippets placed elsewhere make `npm run lint` and the Lefthook pre-commit hook fail. Evidence: [`eslint.config.js`](../../../src/frontend/athlify/eslint.config.js).
- 2026-09-23 - `frontend` `procedure` Register a new UI language by adding `src/i18n/locales/<code>.json` (with a `translation` root key) to `resources` in `src/i18n/index.js`. `LanguageSwitcher` builds its options from the registered resources and uses `Intl.DisplayNames` for the labels. Why: No hard-coded language list needs changing, but a locale that is not registered never appears. Evidence: [`i18n/index.js`](../../../src/frontend/athlify/src/i18n/index.js), [`LanguageSwitcher.tsx`](../../../src/frontend/athlify/src/components/LanguageSwitcher.tsx).
- 2026-09-23 - `frontend` `pitfall` `tsconfig.app.json` enables `noUnusedLocals`/`noUnusedParameters`, and Lefthook runs `npm run typecheck` before each commit, so unused imports left over from experiments block commits. Why: Commented-out or abandoned demo components must also have their imports removed. Evidence: [`tsconfig.app.json`](../../../src/frontend/athlify/tsconfig.app.json), [`lefthook.yml`](../../../lefthook.yml).
- 2026-09-23 - `cross-cutting` `pitfall` Paths in `.agents/docs-root` are resolved relative to the repository root, not to `.agents/`, so the value must be `docs/copilot` (a previous `../docs/copilot` pointed outside the repo and silently disabled the docs skills). `.agents/docs-root.local` is git-ignored for machine-specific paths. Why: A wrong docs root makes every documentation skill run without project context. Evidence: [`.agents/docs-root`](../../../.agents/docs-root), [`docs-root.md`](../../../.agents/skills/project-docs/references/docs-root.md), [`../../CONFIGURATION.md`](../../CONFIGURATION.md).
