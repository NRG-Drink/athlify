- 2026-09-23 - `frontend` `pitfall` Chakra UI CLI snippets in `src/components/ui/` violate `react-refresh/only-export-components` and `@typescript-eslint/no-empty-object-type`. `eslint.config.js` therefore disables both rules for `src/components/ui/**`. Put generated snippets there and keep hand-written components outside that folder. Why: Snippets placed elsewhere make `npm run lint` fail. - 2026-09-23 - `frontend` `procedure` Register a new UI language by adding `src/i18n/locales/<code>.json` (with a `translation` root key) to `resources` in `src/i18n/index.js`. `LanguageSwitcher` builds its options from the registered resources and uses `Intl.DisplayNames` for the labels. Why: No hard-coded language list needs changing, but a locale that is not registered never appears. Evidence: [`i18n/index.js`](../../../src/frontend/athlify/src/i18n/index.js), [`LanguageSwitcher.tsx`](../../../src/frontend/athlify/src/components/LanguageSwitcher.tsx).

- 2026-09-20 - `frontend` `verified` `@vitejs/plugin-react` v6 uses an oxc/rolldown-based transform and no longer accepts a `babel` option, so `babel-plugin-relay` is wired through the separate `@rolldown/plugin-babel` plugin (`babel({ plugins: ['relay'] })` in `vite.config.ts`); `vite-plugin-relay` is installed but not used. Why: Passing `babel: { plugins: ['relay'] }` to `react()` fails typechecking and is silently ignored at runtime. Evidence: `src/frontend/athlify/vite.config.ts`, `node_modules/@vitejs/plugin-react/dist/index.d.ts`.
- 2026-09-20 - `frontend` `verified` GraphQL client data access uses Relay (`react-relay`/`relay-runtime`), with `relay.config.json` pointing at a locally committed `schema.graphql` and generated artifacts under `__generated__/`. The schema is refreshed via `npm run schema:export`, which fetches SDL from the running backend's `?sdl` query parameter (HotChocolate) rather than introspection, because introspection-based tools strip the custom schema-search types HotChocolate's schema references. Why: `relay-compiler` needs the exact SDL the server serves; stripped introspection schemas fail compilation with "Reference to undefined type '__Type'". Evidence: `src/frontend/athlify/relay.config.json`, `src/frontend/athlify/scripts/export-schema.mjs`.
- 2026-09-20 - `frontend` `verified` `RelayEnvironment` (`src/RelayEnvironment.ts`) points at `http://localhost:5095/graphql/` by default, overridable via `VITE_GRAPHQL_ENDPOINT`; components using `useLazyLoadQuery` must be wrapped in a `Suspense` boundary (see `ChartBodyStatsHybrid.tsx`). Why: Relay's lazy query hook suspends the component tree until data resolves. Evidence: `src/frontend/athlify/src/RelayEnvironment.ts`, `src/frontend/athlify/src/components/ChartBodyStatsHybrid.tsx`.

Why: The missing generated query types look like real type errors. Evidence: [`.gitignore`](../../../.gitignore), [`relay.config.json`](../../../src/frontend/athlify/relay.config.json).
- 2026-09-26 - `frontend` `superseded` ~~The frontend is an npm workspace with dependencies hoisted to the repository root; add packages from the root with `npm i -D <pkg> -w src/frontend/athlify`.~~ Superseded: the frontend is now a standalone npm package; see the next entry.
- 2026-09-26 - `frontend` `pitfall` The frontend is a standalone npm package: run all npm commands inside `src/frontend/athlify/`, which holds the only `package.json`, `package-lock.json` and `node_modules`. Do not create a `package.json` or `node_modules` in the repository root. Why: Node resolves packages from parent folders, so a stray root `node_modules` hides missing frontend dependencies until a clean checkout fails. Evidence: [`package.json`](../../../src/frontend/athlify/package.json).
- 2026-09-26 - `frontend` `verified` Chakra/Ark components and `next-themes` need `matchMedia`, `ResizeObserver`, `scrollTo` and `scrollIntoView`, which jsdom lacks; `src/tests/setup.ts` stubs them. jsdom ignores CSS media queries, so the desktop nav and the mobile drawer trigger both exist in tests. Scope queries with `within` the named `navigation` landmark or the open `dialog`, and verify breakpoint visibility in a real browser. Why: Unscoped queries match duplicate links, and missing stubs crash Chakra components. Evidence: [`src/tests/setup.ts`](../../../src/frontend/athlify/src/tests/setup.ts), [`AppLayout.test.tsx`](../../../src/frontend/athlify/src/tests/layouts/AppLayout.test.tsx).
- 2026-09-26 - `frontend` `durable-rule` Navigation links use Chakra `Link asChild` wrapping react-router `NavLink`. `NavLink` sets `aria-current="page"`, and active styling uses Chakra's `_currentPage` condition, not a custom class. URL paths come only from `src/navigation/paths.ts`. Why: Tests and assistive technology assert on `aria-current`, and one path source keeps nav and routes in sync. Evidence: [`PrimaryNav.tsx`](../../../src/frontend/athlify/src/layouts/PrimaryNav.tsx), [`ADR-004`](adr/ADR-004-react-router-data-mode.md).
- 2026-09-26 - `frontend` `durable-rule` Every view wraps its content in `Page` (`src/components/Page.tsx`) and passes a `status`; children render only when the status is `ready`. Tests render the real route table via `renderRoute()` in `src/tests/utils/renderRoute.tsx`. Test files live in `src/tests/`, mirroring the `src/` structure, not next to the code. Why: Keeps loading/empty/error handling and page titles consistent across views. Evidence: [`Page.tsx`](../../../src/frontend/athlify/src/components/Page.tsx), [`routes.tsx`](../../../src/frontend/athlify/src/routes.tsx).
- 2026-09-26 - `frontend` `pitfall` Chakra style props reference gradient tokens by name without the category prefix: `bgImage: 'indicator'` works, `bgImage: 'gradients.indicator'` is emitted as an invalid value and silently renders nothing. Why: The nav indicator was invisible until the prefix was removed; tests can't catch it because jsdom does not paint. Evidence: [`PrimaryNav.tsx`](../../../src/frontend/athlify/src/layouts/PrimaryNav.tsx), `node_modules/@chakra-ui/react/dist/esm/preset-base.js` (`backgroundImage` values).
- 2026-09-26 - `frontend` `verified` `createSystem(defaultConfig, config)` deep-merges the custom config: overriding `bg`/`fg`/`border` keeps untouched defaults such as `bg.emphasized`, and a partial `recipes.button.base` keeps all other default button styles. Why: Theme overrides only need the changed keys. Evidence: [`theme/index.ts`](../../../src/frontend/athlify/src/theme/index.ts), [`system.test.ts`](../../../src/frontend/athlify/src/tests/theme/system.test.ts).
- 2026-09-26 - `frontend` `durable-rule` Theme colors change only in `src/theme/palette.ts` (values) and `src/theme/semantic.ts` (meaning); `npm test` then checks contrast in both modes. Brand cyan fails as text in light mode and logo cobalt fails on the dark navy, so each mode's nav indicator uses a different half of the logo gradient. Why: The contrast test caught cobalt at 1.7:1 on navy, which a design review had missed. Evidence: [`contrast.test.ts`](../../../src/frontend/athlify/src/tests/theme/contrast.test.ts), [`ADR-005`](adr/ADR-005-theme-tokens.md).
- 2026-09-26 - `frontend` `pitfall` Use `chakra.svg` for inline SVGs that need style props; `<Box as="svg">` does not accept SVG attributes such as `viewBox` in TypeScript. Inline SVG gradients need a per-instance id (`useId()`, sanitized for `url(#…)`), because the header and the drawer can render the same mark at once. Why: Duplicate ids make the second mark reference the first gradient. Evidence: [`BrandMark.tsx`](../../../src/frontend/athlify/src/components/BrandMark.tsx).
- 2026-09-26 - `frontend` `verified` Fonts are self-hosted through `src/theme/fonts.ts` (imported by `main.tsx`): `@fontsource-variable/inter` registers the family `'Inter Variable'`, and `@fontsource/barlow-semi-condensed/600.css` plus `600-italic.css` register `'Barlow Semi Condensed'`. Token family names must match exactly. Why: A mismatched name silently falls back to the system font. Evidence: [`theme/fonts.ts`](../../../src/frontend/athlify/src/theme/fonts.ts), [`theme/index.ts`](../../../src/frontend/athlify/src/theme/index.ts).
