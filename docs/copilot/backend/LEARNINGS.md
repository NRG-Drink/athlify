Why: Repeated imports must not corrupt a user's history or undo an intentional deletion. Evidence: [`../../concept/activity-management.md`](../../concept/activity-management.md), [`../../concept/api-design.md`](../../concept/api-design.md).

- 2026-09-20 - `backend` `verified` The API now enables a `FrontendDev` CORS policy (`http://localhost:5173`) so the local Vite dev server can call the GraphQL endpoint. Why: Without CORS, browser requests from the frontend dev origin to `http://localhost:5095/graphql/` are blocked. Evidence: `src/backend/Athlify.Api/Program.cs`.
- 2026-09-20 - `backend` `verified` HotChocolate serves its raw SDL via `GET {endpoint}?sdl` on a running instance, which is safer for local tooling than `dotnet run -- schema export` when the dev server is already running (that command fails trying to overwrite the locked `apphost.exe`). Why: Frontend Relay tooling needs the schema without stopping the backend process. Evidence: `src/frontend/athlify/scripts/export-schema.mjs`.
- 2026-09-23 - `backend` `verified` GraphQL types are discovered by Hot Chocolate source generation. Declare operations in `[QueryType]` / `[MutationType]` `static partial` classes. The generated registration method is `AddTypes()`, named after `[assembly: Module("Types")]`. Why: A resolver class that is not `static partial`, or a renamed module, silently drops operations from the schema. Evidence: [`ModuleInfo.cs`](../../../src/backend/Athlify.Api/Properties/ModuleInfo.cs), [`BodyStatsQuery.cs`](../../../src/backend/Athlify.Api/Queries/BodyStatsQuery.cs), [`Program.cs`](../../../src/backend/Athlify.Api/Program.cs).
- 2026-09-23 - `backend` `procedure` Endpoint tests use TUnit's `TestWebApplicationFactory<Program>` through `WebApiTestBase`, which replaces `IDbSeeder` with `SeedNothing` so each test host starts with an empty database. `Program` must stay `public partial` for the factory. Why: Tests that expect seeded data will fail, and removing `public partial` breaks the test host. Evidence: [`MyWebApplicationFactory.cs`](../../../src/backend/Athlify.Api.Tests/MyWebApplicationFactory.cs).

- 2026-09-30 - `cross-cutting` `open` In the dev container, Aspire starts PostgreSQL on the host Docker daemon (docker-outside-of-docker) and passes the API `localhost:<published port>`, which points at the dev container itself and causes `NpgsqlException: The operation has timed out`. The container therefore runs with `--network=host` (`runArgs` in `devcontainer.json`, added 2026-10-01). Why: Without it the API cannot reach the database. Verify after the next container rebuild and then change the status to `verified`. Evidence: [`devcontainer.json`](../../../.devcontainer/devcontainer.json), [`AppHost.cs`](../../../src/backend/Athlify.AppHost/AppHost.cs).
- 2026-10-01 - `cross-cutting` `verified` Aspire resources show as `running` inside the dev container while their endpoints are unreachable from the host, because DCP binds every endpoint (including the dashboard) to `127.0.0.1` inside the container and the container had no published ports; `remote.autoForwardPorts` in `devcontainer.json` is a VS Code setting and is inert under JetBrains Gateway. Diagnose with `docker exec <container> ss -ltnp` (expect `127.0.0.1:<port>`) and `curl http://127.0.0.1:<port>` inside versus outside the container. Why: The resource is healthy, so only the network path explains the failure. Evidence: [`devcontainer.json`](../../../.devcontainer/devcontainer.json), [`AppHost.cs`](../../../src/backend/Athlify.AppHost/AppHost.cs).
- 2026-10-03 - `backend` `procedure` On .NET 10, TUnit tests do not run through `dotnet test` ("Testing with VSTest target is no longer supported"). Run `dotnet run --project Athlify.Api.Tests` from `src/backend/`. While Aspire runs the API from the same folder, add `--artifacts-path <dir>` so the build does not hit the locked `apphost` ("Text file busy"). Why: The default commands fail for reasons unrelated to the code. Evidence: [`Athlify.Api.Tests.csproj`](../../../src/backend/Athlify.Api.Tests/Athlify.Api.Tests.csproj).
- 2026-10-03 - `backend` `verified` `Program.cs` registers the DbContext with `AddNpgsqlDbContext`, which fails at startup without `ConnectionStrings:postgres-db`. `MyWebApplicationFactory` supplies a dummy value and swaps the registrations for EF Core InMemory, one database per factory. Why: Without it every endpoint test fails with "ConnectionString is missing" and no PostgreSQL is needed for tests. Evidence: [`MyWebApplicationFactory.cs`](../../../src/backend/Athlify.Api.Tests/MyWebApplicationFactory.cs).
- 2026-10-03 - `backend` `pitfall` TUnit creates a new web factory, and so a new empty database, for every test. Tests chained with `[DependsOn]` that rely on data from an earlier test fail. Each test creates its own data (see `BodyStatsGraphQl.cs`). Why: The old chain only worked while all tests shared one database. Evidence: [`BodyStatsMutationTests.cs`](../../../src/backend/Athlify.Api.Tests/BodyStatsMutationTests.cs).
- 2026-10-03 - `backend` `verified` Hot Chocolate 16 global IDs: `AddGlobalObjectIdentification()`; `[ID]`, `[ID<T>]` and `[Node(NodeResolverType = …, NodeResolver = …)]` are in `HotChocolate.Types.Relay`. `[ID<T>]` is valid on properties, methods and parameters, not on a return value, so a mutation that returns an ID carries it on the method. Clients receive opaque strings, so tests read `id` as a string. Why: The compiler errors do not name the namespace. Evidence: [`BodyStatsMutation.cs`](../../../src/backend/Athlify.Api/Queries/BodyStatsMutation.cs), [`BodyStats.cs`](../../../src/backend/Athlify.Api/Models/BodyStats.cs), [`ADR-006`](../adr/ADR-006-relay-global-ids.md).
- 2026-10-03 - `backend` `verified` The committed frontend `schema.graphql` can be produced from the test host with `GET /graphql?sdl` when the running API still has the old schema. Delete removes a measurement's notes explicitly because the existing PostgreSQL foreign key has no cascade. Why: Schema export and delete would otherwise depend on restarting the Aspire app or on a migration. Evidence: [`BodyStatsMutation.cs`](../../../src/backend/Athlify.Api/Queries/BodyStatsMutation.cs).
- 2026-10-03 - `backend` `verified` Cursor paging in Hot Chocolate 16.6 with EF Core: the field is a `static` method taking `PagingArguments` and `QueryContext<T>`, ordered through `.With(query, sort => sort.AddDescending(date).AddDescending(id))`, and returns `new PageConnection<T>(await ….ToPageAsync(pagingArgs, ct))`. Do not add `[UsePaging]` (schema build fails) and do not return a bare `Page<T>` (HC then pages the list again with index cursors and `hasNextPage` is wrong). `ModifyPagingOptions` raises the default maximum of 50, and a page of 1000 with nested notes exceeds the default query cost limit. Why: Each of these produced a silent or confusing failure. Evidence: [`BodyStatsQuery.cs`](../../../src/backend/Athlify.Api/Queries/BodyStatsQuery.cs), `ListIsAConnectionThatPagesWithoutSkippingOrRepeating` in [`BodyStatsQueryTests.cs`](../../../src/backend/Athlify.Api.Tests/BodyStatsQueryTests.cs).
- 2026-10-04 - `cross-cutting` `verified` In a JetBrains dev container session (WebStorm 2026.2 split mode) the Markdown preview is rendered by the local thin client, which does not load the bundled Mermaid plugin (it depends on the backend-only module `intellij.json.backend`). Mermaid fences therefore stay plain code even though the backend loads Mermaid and `customizations.jetbrains.plugins` lists it. Open the repository folder in a local WebStorm to preview diagrams; render-check them with `docker run --rm -v "$PWD":/data minlag/mermaid-cli -i /data/<file>.mmd -o /data/<file>.svg` (no Node on the host). Why: Adding plugins to `devcontainer.json` cannot fix the preview. Evidence: thin-client `idea.log` lists Markdown but not Mermaid under loaded plugins, backend `idea.log` loads both; [`devcontainer.json`](../../../.devcontainer/devcontainer.json).
